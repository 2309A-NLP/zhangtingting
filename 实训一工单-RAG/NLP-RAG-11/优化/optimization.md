# NLP-RAG-11 优化建议文档

## 1. 数据质量优化 (优先级: 高)

### 1.1 增加数据量
当前状态：从 421 页 PDF 中只提取了 16 个章节的 323 段文本，生成了 1433 条训练数据。

问题：大部分内容被跳过（公司治理 71-120 页、股份变动 121-135、优先股 136-140、董事报告 141-159、社会责任 164-171、附录 172-421），数据量严重不足。

优化方案：
- 覆盖更多章节：将跳过的章节纳入训练，数据量可翻 2-3 倍
- 更细粒度的段落切分：按空行或小标题拆分，每个段落 500-800 token
- 跨文档负采样：引入其他银行年报作为负例来源

预期：数据量翻倍后 Recall@1 有望到 35%+

### 1.2 改进查询生成
当前 5 种策略质量参差不齐。改进方向：
- 原文摘录：增加词汇替换，防止过拟合
- 关键词替换：使用 WordNet 或 LLM 生成同义词
- 摘要式/追问式：增加多种模板，减少机械感
- 段落融合：限制同章节融合，保证连贯性

### 1.3 分数标定优化
当前正例=1.0，负例=0.5/0.0，过于粗糙。

改进：引入 BM25 计算段落间相似度作为分数。同章节段落 0.7~0.9（弱正例），同域不同章节 0.3~0.5（中等负例），跨域组 0.0~0.2（强负例）。

## 2. 训练超参数优化 (优先级: 高)

### 2.1 Batch Size
| batch_size | 负例数/query | Recall@1 提升 | 速度 |
|---|---|---|---|
| 8 | 7 | +1.02% | 4.3 it/s |
| 16 | 15 | +4.08% | 2.3 it/s |
| 24 | 23 | 待验证 | ~1.5 it/s |

MNRL 的核心是 batch 内负例数，更大的 batch = 更多负例 = 更好效果。

优化方向：梯度累积（batch=8 + accum=2 等效 batch=16 但显存减半）；或用更轻量模型（BGE-small）。

### 2.2 学习率与 Epoch
当前 lr=2e-5，warmupcosine 调度器，合理。可尝试 15-20 epoch + early stopping (patience=3)。损失曲线显示最后 2-3 epoch 仍在下降。

## 3. 损失函数优化 (优先级: 中)

| 损失函数 | 效果 |
|---|---|
| MNRL | **+4.08%** (最优) |
| BatchHardTriplet | 不兼容 (需 sentence+label 格式) |
| CoSENT | 梯度为 0 |
| CosineSimilarity | -8.16% (反而变差) |
| MNSRL | 待测试 (对称版 MNRL) |

MatryoshkaLoss：未启用。启用后在 768/384/192/96/48 多维度优化，提供弹性维度，但训练慢约 20%。

## 4. 性能优化 (优先级: 中)
- ONNX 导出：推理速度提升 2-3x
- FAISS 索引：检索 O(n) -> O(log n)
- 数据缓存：PDF 提取结果缓存到 pickle，避免重复解析
- AMP：已启用，加速约 40%

## 5. 评估方法论优化 (优先级: 中)
- 当前只有 98 条测试数据，统计显著性有限
- 增加测试章节到 5 个
- 人工标注 200 条真实检索场景的测试数据
- 增加 NDCG@K、MAP@K 等排序指标

## 7. 预期效果汇总

| 优化项 | 预估提升 | 难度 | 优先级 |
|---|---|---|---|
| 增加数据量 | +3~5% | 低 | 高 |
| 优化分数标定 | +1~3% | 中 | 高 |
| 梯度累积 + 更大 batch | +2~4% | 低 | 高 |
| 更多 epoch + early stopping | +1~2% | 低 | 中 |
| MatryoshkaLoss | ±0% (弹性维度) | 低 | 中 |
| ONNX + FAISS | 推理 10x 加速 | 中 | 低 |

综合预估：完成高优先级优化后，Recall@1 可达 **38-42%**（当前 31.63%）。
