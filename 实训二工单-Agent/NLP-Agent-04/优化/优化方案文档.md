## 二、失败案例分析

### 2.1 表名错误（13 例）

**问题描述**：LLM 生成了引用数据库中不存在的表的 SQL。

## 三、优化建议

### 3.1 高优先级（预计提升 2-3%）

#### 3.1.1 问题预检机制

**问题**：系统无法识别数据库不支持的问题类型（如股东信息、财务指标等）。

**方案**：在 Pipeline 中增加「问题能力预检」模块

```python
class QuestionCapabilityChecker:
    """检查问题是否在数据库能力范围内"""

    UNSUPPORTED_KEYWORDS = {
        "股东", "控股", "实际控制人", "发起人",
        "专利", "发明专利", "核心技术人员",
        "供应商", "客户", "采购明细",
        "毛利率", "净利率", "资产负债率",
        "招股", "说明书", "招股意向书",
    }

    def check(self, question: str) -> bool:
        """返回 True 表示可回答，False 表示不支持"""
        for keyword in self.UNSUPPORTED_KEYWORDS:
            if keyword in question:
                return False
        return True
```

**预期效果**：减少 13-15 个「表不存在」错误。

---

#### 3.1.2 增强 SQL 安全校验

**问题**：仍有少量非 SELECT 语句被生成。

**方案**：强化 Prompt 约束 + 后置校验

```python
# 在 sql_generator.py 中增强
_DANGEROUS_KEYWORDS = [
    "INSERT", "UPDATE", "DELETE", "DROP", "ALTER",
    "CREATE", "TRUNCATE", "REPLACE", "GRANT", "REVOKE"
]

def validate_sql(self, sql: str) -> tuple[bool, str]:
    sql_upper = sql.upper()
    for keyword in _DANGEROUS_KEYWORDS:
        if re.search(rf"\b{keyword}\b", sql_upper):
            return False, f"禁止使用 {keyword} 语句"
    return True, ""
```

---

### 3.2 中优先级（预计提升 1-2%）

#### 3.2.1 Few-shot 案例扩充

**现状**：当前 few-shot 示例数量不足，对复杂查询（多表 JOIN、嵌套子查询）支持不够。

**方案**：
1. 从 46 个失败案例中人工标注 20-30 个正确 SQL
2. 补充「错误修正」示例（如何从错误 SQL 修正为正确 SQL）

```json
{
  "question": "查询某行业涨幅超过5%的股票数量",
  "sql": "SELECT COUNT(*) FROM A股票日行情表 a JOIN A股公司行业划分表 i ON a.股票代码 = i.股票代码 AND a.交易日 = i.交易日期 WHERE a.交易日 = '20210415' AND i.一级行业名称 = '建筑材料' AND (a.收盘价 - a.昨收盘) / a.昨收盘 * 100 > 5",
  "tables": ["A股票日行情表", "A股公司行业划分表"]
}
```

---

#### 3.2.2 字段名纠错机制

**问题**：LLM 可能使用业务语义字段名而非数据库实际字段名。

**方案**：在 Schema Selector 中增加「字段名标准化」层

```python
# 常见错误映射
FIELD_ALIASES = {
    "主要原材料": None,  # 标记为不存在
    "基金简称": "基金简称",
    "管理费率": "管理费率(%)",
}
```
