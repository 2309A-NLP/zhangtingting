# 45-工单2日程提醒部署文档

## 1. 文档目的

本文档只针对 `工单 02：日程提醒` 当前在 `工单1-10/agent_platform` 中已经实现的内容，给出一份可直接交付的部署说明。

本文以当前代码实际状态为准，不虚构尚未落地的功能。

- 日程创建
- 日程列表查询
- 日程详情查询
- 日程修改
- 日程取消
- `next_trigger_at` 的基础计算

所以这份部署文档部署的是一套“日程提醒领域基础服务”，本质上是 `Schedule CRUD + 触发时间计算` 的交付版本。

## 5. 数据库表结构说明

工单 2 当前核心表为 `schedule`。

### 5.1 表结构

| 字段名 | 类型 | 是否必填 | 说明 |
|------|------|------|------|
| `id` | `int` | 是 | 主键，自增 |
| `content` | `varchar(255)` | 是 | 日程内容 |
| `schedule_date` | `date` | 否 | 日程日期，单次提醒必须有 |
| `schedule_time` | `time` | 是 | 日程时间 |
| `cycle_rule` | `varchar(32)` | 是 | 循环规则 |
| `cycle_value` | `varchar(64)` | 否 | 循环规则补充值 |
| `status` | `varchar(32)` | 是 | 当前状态 |
| `source_text` | `varchar(500)` | 否 | 原始自然语言输入 |
| `next_trigger_at` | `datetime` | 否 | 下次触发时间 |
| `created_at` | `datetime` | 是 | 创建时间 |
| `updated_at` | `datetime` | 是 | 更新时间 |

### 5.2 字段语义说明

`cycle_rule` 当前支持：

- `once`
- `daily`
- `weekday`
- `weekly_custom`
- `interval_days`

`status` 当前支持：

- `active`
- `cancelled`
- `done`

### 5.3 当前实现中的关键行为

- 创建日程时，会根据 `schedule_date + schedule_time` 计算 `next_trigger_at`
- 更新日程时，会重新计算 `next_trigger_at`
- 取消日程时，会把状态改为 `cancelled`，并清空 `next_trigger_at`

当前限制：

- `daily`、`weekday`、`weekly_custom`、`interval_days` 虽然枚举已存在
- 但当前 `next_trigger_at` 计算逻辑仍然是基础版
- 尚未实现真正的循环推进算法

## 13. 常见问题排查

### 13.1 `python -m alembic upgrade head` 没反应

优先检查：

- PostgreSQL 是否已启动
- `.env` 中 `DATABASE_URL` 是否正确
- `docker compose ps` 中 `postgres` 是否为 `healthy`

### 13.2 `Copy-Item` 命令报错

原因通常是你在 `CMD` 里执行了 PowerShell 命令。

处理方式：

- 在 `PowerShell` 里用 `Copy-Item`
- 在 `CMD` 里改用 `copy`

### 13.3 `dev.ps1 run` 没反应或弹编辑器

建议统一使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1 run -Port 8110
```

不要直接在非 PowerShell 环境里简写执行。

### 13.4 端口被占用

如果 `8110` 被占用，改用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1 run -Port 8120
```

### 13.5 健康检查里除了数据库外还有其他依赖失败

这是因为当前仓库的健康检查按平台统一底座设计，会额外检查：

- Redis
- MinIO
- Milvus

如果你只是跑工单 2 的最小化部署，这些项可能显示未连接，但不影响日程 CRUD 本身。

如果想让健康检查全部通过，建议直接启动完整 compose。
