# 最终作业完成说明

## 1. 项目概述

本项目为“记账本智能体 Agent”课程作业实现版本，目标是构建一个面向家庭场景的自然语言记账助手。系统围绕 `prompt.md` 中的要求，实现了收支记录新增、明细查询、分类统计、删除确认、信息补全追问、数据库持久化与基础异常处理等能力。

本系统的定位是：

- 面向家庭成员（爸爸、妈妈、女儿）的记账智能体
- 支持自然语言输入
- 所有账目数据写入 SQLite 数据库 `money_notes`
- 支持对话式确认、查询与删除

## 2. 作业功能梳理

### 2.1 已实现功能总览

当前课程作业版本已经完成以下核心功能：

1. 新增支出记录
2. 新增收入记录
3. 查询某时间范围内的家庭账目明细
4. 按成员统计支出
5. 按类别/关键词统计支出
6. 按时间/事项进行精确查询
7. 删除记录并二次确认
8. 缺失字段追问补全
9. 非记账输入返回欢迎语
10. 数据库写入后校验
11. 数据库失败重试
12. 多笔账目拆分识别与统一确认
13. 最近记录引用查询
14. 最近批次记录序号引用查询
15. 成员别名归一化与部分模糊指代处理
16. 重复记录提示确认

### 2.2 功能说明表

| 功能模块 | 说明 | 示例 |
|---|---|---|
| 新增支出 | 识别日期、成员、金额、事项，确认后写库 | “今天妈妈买菜88元” |
| 新增收入 | 识别收入类关键词并写库 | “7月5日妈妈收到报销1000元” |
| 明细查询 | 按时间范围、成员范围查询账目 | “看下这个月家里花钱明细” |
| 成员统计 | 统计某个成员在某个时间范围内的消费 | “这个月女儿花了多少钱” |
| 类别统计 | 按事项或关键词统计花费 | “我这个月买书花了多少钱” |
| 精确查询 | 查询某笔事项发生在哪天 | “我哪天买的三体” |
| 删除记录 | 先查后删，必须确认后执行 | “删除女儿报旅游团的费用” |
| 缺失追问 | 缺成员/金额/日期/事项时主动补问 | “今天买东西” |
| 重复检测 | 若记录已存在，先提示再决定是否重复写入 | 再次输入“今天妈妈买菜88元” |

### 2.3 关键增强点

为了让作业表现更完整，当前版本还补充了以下增强能力：

- 支持 `老妈`、`老婆`、`老公`、`闺女` 等别名映射
- 支持 `今天`、`昨天`、`前天`、`大前天`、`上周五`、`上个月`、`这个月` 等时间表达
- 支持最近记录引用，如：
  - “那笔多少钱”
  - “那是谁买的”
- 支持最近批次记录引用，如：
  - “第一笔多少钱”
  - “第二笔是谁的”
  - “把第一笔删掉”

## 4. 数据库字段设计

### 4.1 数据表名称

- 表名：`money_notes`

### 4.2 字段设计表

| 字段名 | 类型 | 约束 | 含义 | 示例 |
|---|---|---|---|---|
| `id` | INTEGER | 主键、自增 | 记录唯一编号 | 1 |
| `date` | TEXT | NOT NULL | 交易日期，格式 `YYYY-MM-DD` | `2026-06-08` |
| `member` | TEXT | NOT NULL | 家庭成员 | `妈妈` |
| `type` | TEXT | NOT NULL，限定收入/支出 | 收支类型 | `支出` |
| `category` | TEXT | NOT NULL | 收支类别/事项 | `买菜` |
| `amount` | REAL | NOT NULL，且大于 0 | 金额 | `88.0` |
| `note` | TEXT | 默认空字符串 | 原始备注或补充说明 | `今天妈妈买菜88元` |

### 4.3 设计说明

1. `id`
   - 作为主键，用于唯一定位一条记录。
   - 删除时可通过 `id` 精准删除。

2. `date`
   - 采用 `TEXT` 存储，统一为 `YYYY-MM-DD` 格式。
   - 便于与 SQLite 的字符串日期比较配合使用。

3. `member`
   - 只保存标准化后的家庭成员名称，如：`爸爸`、`妈妈`、`女儿`。
   - 用户输入中的别名会先做归一化再入库。

4. `type`
   - 只允许 `支出` 或 `收入`。
   - 用于区分消费与进账。

5. `category`
   - 保存事项或类别，如：`买书`、`买菜`、`报销`。
   - 支持后续做分类统计。

6. `amount`
   - 统一保存数值，不保存“元”“块”等单位。
   - 约束为正数，支出与收入通过 `type` 字段区分。

7. `note`
   - 保存原始说明或补充信息，方便做关键词查询。
   - 例如查询“三体”时，可通过 `note` 辅助命中。

### 4.4 实际建表语句

```sql
CREATE TABLE IF NOT EXISTS money_notes (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    date     TEXT    NOT NULL,
    member   TEXT    NOT NULL,
    type     TEXT    NOT NULL CHECK (type IN ('支出', '收入')),
    category TEXT    NOT NULL,
    amount   REAL    NOT NULL CHECK (amount > 0),
    note     TEXT    DEFAULT ''
);

CREATE INDEX IF NOT EXISTS idx_member_date ON money_notes(member, date);
```

### 4.5 索引设计说明

- `idx_member_date`
  - 建立在 `(member, date)` 上
  - 便于支持“按成员 + 时间范围”的高频查询
  - 如：`这个月女儿花了多少钱`

## 6. 项目实现对应关系说明

### 6.1 主要代码文件

| 文件路径 | 作用 |
|---|---|
| `agent/guardrails.py` | 规则型对话主逻辑，负责意图识别、字段提取、状态流转 |

### 6.2 关键实现特点

1. 规则优先
   - 课程作业版本优先采用规则与状态机方式实现，便于控制流程与验收。

2. 状态管理
   - 通过对话状态管理待确认记录、补槽流程、删除确认和重复记录确认。

3. 数据持久化
   - 所有新增、查询、删除都通过数据库执行，不依赖纯对话内存保存结果。

4. 可测试性
   - 使用独立临时数据库运行验收测试，保证测试互不干扰。
